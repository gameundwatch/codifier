# codifier-collect — 決断を集める

<!-- コードと履歴から、決まっていることを二つの入口で拾う -->

## Background

コードは選ばれた案しか保存しない。捨てた案と、それを捨てた経緯は履歴にある。
コードだけを読んで設計や要件が分かるという通説は、選ばれた案を読めることを
指しているに過ぎない。

決まっているかどうかを人に聞いて回ると、既存の実装に対しては終わらない。
決まっている証拠は履歴の側にある。

ただし、捨てた案を持たずに成立する決断もある。定義がそれで、名前と対象を結びつける
行為そのものが決断にあたる。外から名指しされている識別子は、変えれば名指ししている
全箇所が壊れるため、既に決まっている。この分だけコードが指す決断の写像が書ける。

## Availability

- 走査範囲を渡すと、その範囲のコードと履歴から決断の候補が挙がる
    - 範囲が決まるまで走査は始まらない
    - 件数が先に示される
- 入口が二つあり、それぞれの件数が分けて示される
    - 履歴からは徴候で拾う
    - コードからは定義で拾う
- 徴候を持つものだけが挙がる
    - 反復・収束・差戻し・不動の四つ
    - いずれか一つを持てば挙がる
- 定義のうち、定義スコープの外から名指しされているものだけが挙がる
    - 名指しは本体とテストの双方を数える
    - ドキュメント内の言及は数えない
    - 誰も名指ししていない公開識別子は挙がらない
- 公開された識別子については、名前ごとに命名の決断が挙がる
    - 名前、対象、どこから名指しできるかが書かれる
    - 同じ概念に別の綴りが併存していれば、その併存も書かれる
    - 命名規則としてまとめられることはない
- 挙がらなかったものが理由つきで残る
- 途中で問い合わせが来ない
- 候補には決断が成立したコミットの時刻が付く
    - 徴候の側は徴候が成立したコミット、定義の側は初めて外から名指しされたコミット
    - 同じリポジトリを日を変えて集めても同じ値になる
- 公開識別子が改名されると、その命名の決断は覆りとして扱われる
    - 決断事項の名前が黙って書き換わることはない
